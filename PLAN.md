# План: сайт «Внутри себя» — школьный проект по вероятности РПП

## Контекст

Индивидуальный проект Алисы Сидельниковой (8А, МАОУ Лицей 200) по вероятности и статистике: «Расчёт вероятности появления у человека расстройств пищевого поведения». Цель из презентации — информационный сайт с тестом-самопроверкой. Входные данные в `input/`: опросник на 29 вопросов (`Вопросы.txt`), презентация с формулой риска (15 слайдов, PDF), 8 макетов сайта «Внутри себя» (`input/reference/`).

Решения, зафиксированные с Антоном:
- Процесс поэтапный: **план → ТЗ → аналитика → дизайн → MVP**, каждый этап показываем и согласовываем.
- Стек: статический сайт (HTML/CSS/JS, без сборки и бэкенда), простые анимации, хостинг для учеников.
- **Данные не храним вообще**: ни сервера, ни localStorage. Повторный результат — только новое прохождение теста.
- Вопросов 29 (из файла), формула адаптируется: F4 — среднее по q16–q29.

## Этапы и артефакты (после каждого — стоп и согласование)

### Этап 1. Техзадание → `docs/ТЗ.md`
Цели, аудитория (школьники 13–17), список страниц, функциональные и нефункциональные требования, ограничения. Ключевые пункты, которые обязательно фиксируем:
- Страницы по макетам: главная, «О РПП», тест, результат (3 состояния: низкий/средний/высокий), «Техники самопомощи», статья «Как поговорить с близким о РПП», + «Рекомендации» и список «Статьи» (макетов нет — делаем в том же стиле).
- **Конфликт с макетами**: кнопка «Сохранить результат» и карточка «Дневник настроения» подразумевают хранение — решаем явно: заменить на «Распечатать результат» (`window.print`, ничего не хранит) либо убрать. В макете теста «Вопрос 1 из 25» — у нас 29, это осознанное отличие.
- Показ результата: уровень риска + значение R (2 знака, как 2.27 и 3.16 в презентации) + разбивка по факторам F1–F4 — сайт наглядно демонстрирует формулу, это усиливает защиту проекта.
- Дисклеймер «это не диагноз» и блок «Куда обратиться» — обязательны (уже есть в макетах).

### Этап 2. Аналитика → `docs/Аналитика.md`
Карта сайта, user flow теста, контент-модель страниц, полная модель подсчёта:
- Шкала ответов **1–4** (Почти никогда=1 … Почти всегда=4). Подтверждение: слайд «3.16 **из 4**» — максимум 4 достижим только при шкале 1–4.
- Факторы как в презентации (семантику не перекраиваем, индексы наследуем): F1=ср(q1–q4) когнитивные установки, F2=ср(q5–q8) образ тела, F3=ср(q9–q15) пищевое поведение, F4=(q16+…+q29)/14 внешние факторы.
- **R = 0.25·F1 + 0.25·F2 + 0.3·F3 + 0.2·F4**. Пороги с явной конвенцией границ: R<1.5 низкий, 1.5≤R<2.5 средний, R≥2.5 высокий.
- Особые вопросы: q28 (5 вариантов) → баллы 1,2,3,4,4; q29 без вариантов в файле — **придумываем шкалу влияния 1–4** (отметить в документе, что это наше дополнение). Одной строкой задокументировать адаптацию формулы 30→29 вопросов — готовый ответ для защиты.
- Контент: тексты всех страниц. **Телефоны доверия из макетов не копировать** — обязательная проверка каждого номера через WebSearch по официальным источникам (детский телефон доверия, МЧС и т.п.); в контент попадают только подтверждённые.

Перед показом каждого документа — самопроверка по методике superpowers: заглушки, противоречия, двусмысленности, объём.

### Этап 3. Дизайн → `docs/Дизайн.md`
Дизайн-система по референсам: палитра (светлая пастель; акценты уровней — зелёный/жёлтый/розовый), типографика, компоненты (карточки, кнопки, прогресс-бар, хедер/футер), простые анимации (появление при скролле, переходы вопросов, прогресс). Открытый вопрос этапа: фото как в макетах (бесплатный сток с лицензией) vs лёгкий CSS/SVG-декор — предложить оба, согласовать.

### Этап 4. MVP → `site/`
```
site/
  index.html            — главная
  about.html            — О РПП
  test.html             — тест (вопрос за вопросом, прогресс, Назад/Далее) + экран результата
  help.html             — техники самопомощи
  articles.html         — список статей
  article-razgovor.html — «Как поговорить с близким о РПП»
  recommendations.html  — рекомендации
  css/styles.css, js/quiz.js, js/main.js, assets/
```
Тест — механика на одной странице (JS, состояние в памяти), подсчёт на клиенте, результат сразу, «Пройти заново» сбрасывает всё. Никаких запросов наружу и записи данных. Вопросы — данными в `js/quiz.js` (массив с текстами, вариантами, привязкой к факторам).

Перед этапом — детальный план реализации (скилл writing-plans), в разработке: frontend-design для вёрстки, TDD для логики подсчёта в `quiz.js`.

### Этап 5. Верификация (скилл verification-before-completion: сначала проверки, потом заявления о готовности)
- Юнит-проверка формулы на граничных векторах: все ответы 1 → R=1.00 (низкий); все 4 → R=4.00 (высокий); подобранный средний вектор → средний; ровно 1.5 и 2.5 → по конвенции границ.
- Прокликать сайт в Chrome (browser-tools): полный проход теста, «Назад», перезапуск, все 3 состояния результата, мобильная ширина.
- Хостинг (GitHub Pages и т.п.) — отдельный согласуемый шаг после MVP; репозитория ещё нет (`git init` только с одобрения).

## Безопасность (формально, без фанатизма)

Сайт открыт для учеников по ссылке, но закрыт от роботов; персональных данных нет by design:
- `robots.txt` в корне: `User-agent: *` + `Disallow: /` — поисковые роботы по сайту не ходят.
- `<meta name="robots" content="noindex, nofollow">` на каждой странице — страховка от попадания в выдачу.
- Ноль сбора данных: нет форм отправки, кук, аналитики, внешних трекеров и запросов к сторонним серверам; тест считается целиком в браузере.
- Внешние ссылки (горячие линии, ресурсы) — только HTTPS и с `rel="noopener"`.
- HTTPS обеспечивает хостинг (GitHub Pages — из коробки). На этом всё, не увлекаемся.

## Критичное
- Аудитория — реальные подростки: бережный тон, дисклеймеры, только проверенные номера помощи. Неверный номер горячей линии — худший возможный баг проекта.
- Исходники в `input/` не трогаем.
