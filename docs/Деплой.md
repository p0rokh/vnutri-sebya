# Деплой сайта «Внутри себя»

Сайт публикуется на VDS timeweb.cloud: nginx отдаёт статику из `site/`, рядом работает
мини-API сбора анонимных результатов теста (`server/app.py`, Python stdlib + SQLite).
Сервер сам подтягивает обновления из GitHub (`main`) каждые 5 минут.

## Сервер

- **Хостинг:** timeweb.cloud, VDS
- **ОС:** Ubuntu 26.04
- **Ресурсы:** 1 CPU × 3.3 ГГц, 2 ГБ RAM, 30 ГБ NVMe, канал 100 Мбит/с
- **Домен:** insideoneself.orbitalfeed.ru

## Cloud-init

Конфиг целиком вставляется в поле «Cloud-init» при создании сервера в панели timeweb.cloud
(первая строка обязана быть `#cloud-config`). Первая загрузка занимает 3–5 минут —
идёт обновление пакетов.

```yaml
#cloud-config
# ===== Сайт «Внутри себя» — инициализация VDS timeweb.cloud =====
# Вставить в поле «Cloud-init» при создании сервера (Ubuntu 26.04).
# Лог выполнения на сервере: /var/log/cloud-init-output.log

timezone: Europe/Moscow

package_update: true
package_upgrade: true

packages:
  - nginx
  - git
  - rsync
  - ufw
  - fail2ban
  - certbot
  - python3-certbot-nginx
  - apache2-utils   # htpasswd для страницы статистики

# 1 ГБ swap — страховка от OOM при 2 ГБ RAM
swap:
  filename: /swapfile
  size: 1073741824
  maxsize: 1073741824

write_files:
  # SSH-ключ для root (append — не затираем ключ из панели, если добавишь его там)

    content: |
      server {
          listen 80 default_server;

    content: |
      #!/usr/bin/env bash
      set -euo pipefail
      REPO=https://github.com/p0rokh/vnutri-sebya.git
      DIR=/opt/vnutri-sebya
      WEBROOT=/var/www/vnutri-sebya

          git clone --depth 1 --branch main "$REPO" "$DIR"

      [Unit]

  - path: /etc/systemd/system/vnutri-sebya-deploy.timer

      [Unit]
      Description=Auto-deploy vnutri-sebya every 5 min

      [Timer]
      OnBootSec=2min
      OnUnitActiveSec=5min

      [Install]
      WantedBy=timers.target

  - /usr/bin/flock /run/vnutri-sebya-deploy.lock /usr/local/bin/deploy-vnutri-sebya

  # Включаем сайт в nginx, убираем дефолтную заглушку
  - ln -sf /etc/nginx/sites-available/vnutri-sebya /etc/nginx/sites-enabled/vnutri-sebya && rm -f /etc/nginx/sites-enabled/default && nginx -t && systemctl reload nginx

  - systemctl daemon-reload && systemctl enable --now vnutri-sebya-deploy.timer
  # Файрвол: сначала разрешаем SSH, только потом включаем
  - ufw allow OpenSSH && ufw allow "Nginx Full" && ufw --force enable

  Vnutri-sebya server ready in $UPTIME sec.
  Site: http://insideoneself.orbitalfeed.ru (or by server IP)
  Log: /var/log/cloud-init-output.log
```

## Что делает конфиг

- Ставит nginx, git, rsync, ufw, fail2ban, certbot; обновляет пакеты; таймзона Москва; swap 1 ГБ.
- Добавляет SSH-ключ root'у (`append` — ключ из панели timeweb не затирается). Директива
  `users:` не используется намеренно: на timeweb она ломает root-пароль из панели.
- Клонирует репозиторий в `/opt/vnutri-sebya`, выкладывает `site/` в `/var/www/vnutri-sebya`.
- Включает сайт в nginx (сайт доступен и по домену, и по IP), убирает дефолтную заглушку.
- Включает systemd-таймер `vnutri-sebya-deploy.timer` — автообновление из GitHub каждые 5 минут.
- Поднимает сервис `vnutri-sebya-api` (API результатов на 127.0.0.1:8765, БД в `/var/lib/vnutri-sebya/results.db`),
  подключает nginx-snippet с `/api/*` и закрытой `/stats.html`.
- Настраивает ufw: разрешены только OpenSSH и Nginx Full (80/443).

## После создания сервера

1. Добавить A-запись: `insideoneself.orbitalfeed.ru → IP сервера`.
2. Когда DNS доедет, включить HTTPS (одной командой на сервере):

   ```bash
   certbot --nginx -d insideoneself.orbitalfeed.ru --redirect --agree-tos -m a87skorolev@gmail.com --no-eff-email
   ```

   Продление сертификата автоматическое (`certbot.timer` ставится пакетом).

3. Задать пароль страницы статистики (логин `stats`, пароль — из Keychain Антона):

   ```bash
   htpasswd -c /etc/nginx/vnutri-sebya.htpasswd stats
   ```

## Статистика ответов (бэкенд)

- **Что собираем:** индексы выбранных вариантов по 33 вопросам, R, уровень, F1–F4, время (UTC) и
  версию опросника. **Не собираем:** IP, User-Agent, cookies — nginx пишет `access_log off` на
  `/api/results`, бэкенду IP не передаётся, его `log_message` адрес клиента не печатает.
- **Где смотреть:** `https://insideoneself.orbitalfeed.ru/stats.html` (basic auth, логин `stats`),
  там же кнопка «Скачать CSV» (`/api/export.csv`: UTF-8 с BOM, `;`, время UTC и МСК), список всех
  записей с удалением по одной и «Удалить все записи» (двойной клик для подтверждения;
  `DELETE /api/admin/results[/<id>]`, тоже за паролем).
- **Как устроено:** `server/app.py` — один файл на stdlib, systemd-сервис `vnutri-sebya-api`,
  слушает только 127.0.0.1:8765; nginx проксирует `/api/results` (открыто, `limit_req` 5 запросов/мин
  с IP) и `/api/stats`, `/api/export.csv`, `/stats.html` (basic auth). Код исполняется из
  `/opt/vnutri-sebya/server`, деплой перезапускает сервис, если `server/` менялся. Unit и nginx-конфиги
  деплой **не** копирует — только cloud-init при создании сервера или руками.
- **Повторные отправки:** клиент шлёт результат дважды (после показа результата и после оценки
  проекта) с одним `id`; сервер делает upsert, оценка проставляется один раз.
- **Защита от спама:** только `limit_req` и отсутствие CORS; целенаправленный спам не остановит
  (осознанно). Мусор видно по времени на странице статистики.
- **Бэкап БД:** `python3 -c "import sqlite3; sqlite3.connect('/var/lib/vnutri-sebya/results.db').backup(sqlite3.connect('/root/results-$(date +%F).db'))"`
- **Логи:** `journalctl -u vnutri-sebya-api` · проверка: `curl 127.0.0.1:8765/api/health`
- **Тесты:** `python3 -m unittest discover -s server -v`

### Включение на уже работающем сервере (октябрь 2026)

Сервер был создан по старому cloud-init без бэкенда. Порядок (всё под root по SSH):

1. **HTTPS — предпосылка:** `certbot --nginx -d insideoneself.orbitalfeed.ru --redirect --agree-tos -m a87skorolev@gmail.com --no-eff-email`.
   Без HTTPS basic auth и ответы подростков ходили бы открытым текстом.
   ⚠️ После этого `cloud-init clean --reboot` затрёт ssl-строки certbot в конфиге nginx — повторный прогон cloud-init больше не безвреден.
2. `apt-get install -y apache2-utils`.
3. Обновить `/usr/local/bin/deploy-vnutri-sebya` (блок с `OLD=` и `try-restart` из cloud-init выше) и выполнить `deploy-vnutri-sebya`, чтобы на сервере появился `server/`.
4. Конфиги: три `cp` из `runcmd` выше, в `/etc/nginx/sites-available/vnutri-sebya` добавить
   `include snippets/vnutri-sebya-api.conf;` внутрь `server { … }`, создать htpasswd (`htpasswd -c … stats`),
   `nginx -t && systemctl reload nginx`.
5. `systemctl daemon-reload && systemctl enable --now vnutri-sebya-api && curl 127.0.0.1:8765/api/health`.
6. Проверки: `curl -X POST https://…/api/results` с валидным телом → 201, повтор → 200,
   `curl https://…/api/stats` без пароля → 401, `/stats.html` в браузере с паролем.

Порядок важен: сначала сервер (basic auth на месте), потом мерж ветки в `main` — иначе
`rsync --delete` на несколько минут опубликует `stats.html` без пароля.

## Обновление сайта

- **Автоматически:** push в `main` → сайт обновится в течение 5 минут.
- **Вручную:** `deploy-vnutri-sebya` по SSH.
- **Отключить автообновление:** `systemctl disable --now vnutri-sebya-deploy.timer`.
- ⚠️ Деплой делает `rsync --delete`: правки файлов прямо на сервере в
  `/var/www/vnutri-sebya` затираются. Все изменения — только через git.

## Отладка

- Лог инициализации: `/var/log/cloud-init-output.log`
- Лог деплоев: `journalctl -u vnutri-sebya-deploy.service`
- Повторный прогон cloud-init после правки конфига в панели: `cloud-init clean --reboot`
  (единственный побочный эффект — SSH-ключ добавится дублирующей строкой, это безвредно).
